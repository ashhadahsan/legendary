The opaque payments service (MOCKPAY_URL) at POST /batch returns {"status":"accepted"} for ANY well-formed {"records":[{"id","amount"}]} payload, but only adds a record to the batch total when its "amount" is a JSON **string** (e.g. "19.99"). Numeric/float amounts are silently dropped — accepted but never counted, so /totals stays 0.0. This made test_billing_reconciliation fail while status was still "accepted". Fix in billing/client.py: serialize amount as str(r["amount"]) in submit_batch. Refund submission (billing/refunds.py) presumably needs the same string treatment at POST /refund.
