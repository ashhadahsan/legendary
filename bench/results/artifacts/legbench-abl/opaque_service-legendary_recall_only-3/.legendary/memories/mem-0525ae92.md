The opaque payments service at $MOCKPAY_URL (endpoints /batch, /refund, /totals, /reset) silently ACCEPTS a batch ({"status":"accepted"}) but only records records whose `amount` is a JSON **string** or a JSON **integer**. A JSON **float** (e.g. 19.99) is dropped, contributing 0.0 to the server-side total.

Probed behavior (POST /batch then GET /totals):
- amount 19.99 (float)  -> batch 0.0  (dropped)
- amount 1999 (int)     -> counted as 1999
- amount "19.99" (str)  -> counted as 19.99
Container must be {"records":[{"id":..,"amount":..}]} — "items"/"entries"/top-level list are ignored.

Fix in billing/client.submit_batch: serialize `amount` as a string, e.g. `"amount": str(r["amount"])`. str(5.00)=="5.0" and str(0.01)=="0.01" are both accepted; 19.99+5.00+0.01 reconciles to 25.00.

Same convention applies to /refund — when implementing billing/refunds.submit_refunds (session 2's task), send amounts as strings the same way.
