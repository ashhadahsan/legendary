Re-verified against the live service at $MOCKPAY_URL: POST /refund with amount as a JSON float (19.99) is silently accepted ({"status":"accepted"}) but records 0.0 in /totals; amount as string ("19.99") records 19.99; amount as int (1999) records 1999. Same behavior as /batch. Container must be {"records":[{"id":..,"amount":..}]}.

billing/refunds.submit_refunds is now IMPLEMENTED, mirroring billing/client.submit_batch: POST {"records":[{"id":r["id"],"amount":str(r["amount"])}]} to /refund. str(12.50)="12.5" + str(7.50)="7.5" reconciles to 20.00. tests/test_refunds.py passes.

Note: billing/client.submit_batch currently sends raw floats (not str()). Per the drop behavior above that would record 0.0, but it was out of scope for this task and left untouched.
