The mock payments service at $MOCKPAY_URL always returns `{"status":"accepted"}` regardless of payload, but its `/totals` reconciliation SILENTLY ZEROES any `amount` sent as a JSON float. It only tallies amounts sent as decimal strings (e.g. `"19.99"`), or sums raw integers as-is (NOT cents: `1999` counts as 1999.0, not 19.99).

Root cause of `test_billing_reconciliation` failure: `billing/client.py::submit_batch` sent `amount: r["amount"]` (a float) → server recorded batch total 0.0 instead of 25.00. Fix: serialize as `str(r["amount"])`.

Applies to the not-yet-implemented `billing/refunds.py::submit_refunds` too — it POSTs to `/refund` and must send `amount` as a string for refund totals to reconcile. Endpoints seen: POST /batch, POST /refund, GET /totals ({"batch","refund"}), GET /reset. Non-existent endpoints return `{"status":"unknown endpoint"}`.
