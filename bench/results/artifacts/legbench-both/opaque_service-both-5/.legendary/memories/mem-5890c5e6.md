The MockPay opaque service (MOCKPAY_URL) always returns {"status": "accepted"} from /refund and /batch regardless of whether the amount actually reconciles. Discovered by probing /reset + POST + /totals: a record with a numeric (float/int) `amount` is accepted but silently dropped from the server-side total (totals stay 0.0), whereas the SAME amount sent as a STRING (e.g. "12.5") reconciles correctly. Payload shape is {"records": [{"id": ..., "amount": ...}]} for both endpoints.

Fix in billing/refunds.py submit_refunds: serialize amount with str(r["amount"]) so tests/test_refunds.py::test_refund_reconciliation reconciles to 20.00.

NOTE: billing/client.py submit_batch has the identical bug — it POSTs float amounts to /batch, so tests/test_billing.py::test_billing_reconciliation fails (batch total 0.0 vs expected 25.0). Same fix (str(amount)) would resolve it, but that was out of scope for the refunds task.
