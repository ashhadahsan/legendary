Re-verified 2026-08-21 against MOCKPAY_URL: the same float-drop quirk documented for /batch also applies to /refund. POSTing {"records":[{"id","amount":10.00}]} returns {"status":"accepted"} but /totals shows refund 0.0. Sending amount as a JSON string ("10.00") reconciles correctly (refund 10.0). Implemented billing/refunds.py submit_refunds by serializing each amount with str(r["amount"]) POSTed to /refund; tests/test_refunds.py passes (12.50+7.50 -> 20.00). The prior memory mem-64b86406 was flagged stale but its core claim is still true.
