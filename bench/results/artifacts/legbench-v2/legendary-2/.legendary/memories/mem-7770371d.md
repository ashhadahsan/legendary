Verified empirically 2026-08-21 against the live MOCKPAY server: POSTing `/refund` with a JSON-float amount returns `{"status":"accepted"}` but `/totals` refund stays 0.0; POSTing the same amount as a string decimal ("12.50") reconciles correctly (totals.refund=12.5).

So `billing/refunds.py::submit_refunds` serializes `"amount": str(r["amount"])` in the payload. This makes test_refunds.py::test_refund_reconciliation pass (expects totals.refund == 20.00 for records summing to 20.00).

Same quirk as the prior /batch memory (mem-974f1ffa). Note: the current billing/client.py::submit_batch still sends raw floats, so test_billing.py may be failing independently — not touched by this task.
