The payments service (MOCKPAY_URL) returns {"status":"accepted"} for any well-formed POST to /batch, but when an `amount` is a JSON float it silently ignores that record, so /totals stays 0.0. It only counts amounts sent as JSON strings ("19.99") or integers. Fix in billing/client.py: serialize amount as a decimal string via format(r["amount"], ".2f"). Verified 19.99+5.00+0.01 -> batch 25.0.

Same contract will apply to refunds.py submit_refunds POSTing to /refund (session 2's task) — send amounts as decimal strings, not floats.

Probing notes: GET / and /schema and /docs return {"status":"unknown endpoint"}; use /reset before each batch.
