The payments service (MOCKPAY_URL) `/refund` endpoint behaves like `/batch`: it returns `{"status":"accepted"}` regardless, but only ADDS a record to the refund total when its JSON `amount` field is a string. A JSON float `amount` is silently recorded as 0 — request looks accepted while `/totals` refund stays 0.0.

Verified by probing the live server (2026-08-21): float `1.23` → refund 0.0; strings "12.50"+"7.50" → refund 20.0.

Fix in `submit_refunds` (billing/refunds.py): serialize each amount as a string, e.g. `"amount": str(r["amount"])`. Mirrors `submit_batch`. Payload envelope must be `{"records": [...]}`, POST /refund with Content-Type application/json. `/reset` and `/totals` are GET. This makes tests/test_refunds.py::test_refund_reconciliation pass.
