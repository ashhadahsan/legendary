The payments service (MOCKPAY_URL) `/batch` endpoint returns `{"status":"accepted"}` regardless, but only ADDS a record to the batch total when its `amount` field is a JSON string (or integer). A JSON float `amount` is silently recorded as 0 — so the request looks accepted while `/totals` stays 0.0.

Fix in `submit_batch`: serialize each amount as a string, e.g. `"amount": str(r["amount"])`. With records 19.99/5.00/0.01 this yields batch total 25.00.

Contract notes discovered by probing the live server:
- payload envelope must be `{"records": [...]}` (key `items` or `batch` → `{"status":"bad request"}`).
- `/reset` and `/totals` are GET (test fixture uses urllib urlopen). curl -X POST /reset returns "unknown endpoint".
- integer amounts are summed as-is (so cents 1999 → 1999, NOT 19.99) — use strings, not integer cents.
