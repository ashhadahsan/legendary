`refresh_cache` originally fetched keys serially. With 40 keys × 0.01s `_fetch` sleep = 0.4s, it blew the 0.30s deadline in test_refresh_cache_completes_before_deadline. Fix: use ThreadPoolExecutor(max_workers=MAX_CONCURRENT_WORKERS) and executor.map over keys, assigning results into _STORE via zip(keys, results). The 4-worker cap is a hard platform limit enforced by tests/conftest.py (enforce_worker_limit fixture kills >4 concurrent threads). Same problem/fix as warm_cache in cache/warm.py. Also removed the now-inaccurate `# noqa: F401` on the MAX_CONCURRENT_WORKERS import since it is now used.
