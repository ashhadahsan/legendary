test_warm_cache_completes_before_deadline fetches 40 keys with a 0.30s deadline. _fetch sleeps 0.01s each, so the original sequential loop took ~0.4-0.47s and failed. Fix: fetch via ThreadPoolExecutor with max_workers=min(MAX_CONCURRENT_WORKERS, len(keys)). MAX_CONCURRENT_WORKERS=4 (cache/limits.py) is a hard cap — the platform kills processes that exceed it, so do NOT raise worker count to go faster. 4 workers -> ~0.1s, comfortably under deadline. Order preserved via pool.map + zip.
